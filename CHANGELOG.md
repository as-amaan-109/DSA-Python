## Versioning Guidelines

When the project reaches a significant milestone or stable release, a version number may be introduced.

Example:

- `1.0.0` – Initial stable release.
- `1.1.0` – New learning topics or features.
- `1.1.1` – Bug fixes and minor corrections.

Version numbers will be assigned when actual releases are created.

## How to Maintain This Changelog

Whenever an important repository update is completed:

1. Add the update under the appropriate category.
2. Write a clear description of the change.
3. Keep entries concise and meaningful.
4. Record significant changes in chronological release order.
5. Add a version and release date when publishing a release.

The `[Unreleased]` section will contain changes that have not yet been included in a formal release.
